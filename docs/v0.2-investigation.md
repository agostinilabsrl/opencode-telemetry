## Remaining Risk

`Session.parentID` is optional (`parentID?: string`) in the SDK type. Whether opencode *actually sets it* when spawning subagent sessions is unconfirmed empirically. It requires a live Conductor session to verify.

### How to verify once data exists

```sql
-- Step 1: find a Conductor session with dispatches
SELECT session_id, primary_agent, total_turns, total_tool_calls, est_cost_usd
FROM sessions
WHERE primary_agent = 'conductor' AND total_tool_calls >= 5
ORDER BY est_cost_usd DESC LIMIT 5;

-- Step 2: check if children were linked
SELECT session_id, parent_session_id, primary_agent, total_turns, est_cost_usd
FROM sessions
WHERE parent_session_id = '<chosen_session_id>'
   OR session_id = '<chosen_session_id>'
ORDER BY started_at;
```

If no child rows appear, opencode does not populate `parentID` and Phase 1 fallback work is needed (timestamp-based correlation or `spawned_session_id` tracking via tool call events).

## Decision

Since code analysis returns Outcome A, **Phase 1 is skipped**. Proceeding directly to Phase 2 schema enrichment. The investigation outcome is documented here and in `NOTES.md §15`.
